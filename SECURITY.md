# Security maintenance

Use [OWASP Top 10:2025](https://top10.owasp.org/2025/) and applicable public-site Level 1 controls from [ASVS 5](https://owasp.org/projects/asvs) as the baseline. This is a scoped portfolio review, not ASVS certification or a penetration test.

- **Secrets/environment:** never commit real `.env` files, credentials, private keys or tokens. `.env.example` contains empty placeholders only. `NEXT_PUBLIC_*` values are public in browser/build output; the only current variable is the canonical `NEXT_PUBLIC_SITE_URL`. It must be credential-free HTTPS, with HTTP allowed only for localhost. Keep future secrets server-only in the deployment environment. Rotate/revoke any exposed credential immediately and check history/build artifacts before cleanup.
- **Inputs/server boundaries:** current routes are read-only, with no forms, API handlers, server actions, auth or backend fetches. Category queries use a fixed allowlist; slug lookup resolves published projects only. React escapes copy; JSON-LD escapes `<`. Do not introduce raw HTML, eval, query-driven redirects or arbitrary server fetches. New write endpoints need server-side schema/size validation, authorization, abuse limits, safe errors and CSRF/origin controls appropriate to their authentication.
- **External content:** published data must be supplied/approved and redacted. Links accept credential-free HTTPS only; new-tab links retain `noopener noreferrer`. Embed URLs are rebuilt from exact supported hosts and validated IDs. Video loads only after activation, with limited iframe permissions. Local video URLs stay inside `/media/` and use `.mp4`; external media origins must be approved before publishing. Posters/images remain local through Next Image. Never publish signed/private media URLs or secrets in query strings.
- **Dependencies:** preserve `package-lock.json`; use `npm ci`, then `npm audit` including development dependencies. Review exploitability and release notes; prefer compatible fixes, rerun QA, and report breaking upgrades rather than forcing them. Audit result is time-limited and does not prove absence of vulnerabilities.
- **Headers/CSP:** `next.config.ts` uses `src/lib/securityHeaders.ts`. Enforced CSP restricts base URLs, objects and parent framing; existing nosniff, SAMEORIGIN, referrer and camera/microphone/geolocation policies remain. Resource CSP is production **Report-Only**. Do not silence violations by adding broad script permissions. See the inventory below before enforcement.
- **Deployment:** verify HTTPS redirects and actual response headers on the canonical domain, preview and error/static routes. [Vercel supplies HSTS by default](https://vercel.com/docs/headers/response-headers); this app does not override it or add preload/includeSubDomains without domain verification. Other hosts must configure HSTS after TLS checks. No production domain is configured or remotely audited yet. Retain noindex for demos/unconfigured deployment, draft 404s, lazy media, native keyboard/touch and shared reduced-motion alternatives.
- **Reporting/updates:** privately contact the repository owner through an established channel or GitHub private vulnerability reporting if enabled; do not post secrets or exploit details in public issues. Record impact/reproduction without sensitive data, triage promptly, rotate exposed credentials, make a focused patch, run lint/typecheck/tests/build plus relevant browser checks, and verify deployed headers/behavior after release.

## CSP origin inventory and enforcement gate

Application JS/CSS, Next runtime/prefetch, images and `next/font` fonts are same-origin. Google Fonts are fetched at **build time**, not by the browser. GSAP requires dynamic inline styles. Next static hydration scripts and JSON-LD currently use inline script elements; a script-src self-only Report-Only policy will report these without blocking them. No analytics, remote JS, CMS, API or browser font origin is configured.

Supported iframe origins: `https://www.loom.com`, `https://www.youtube-nocookie.com`, `https://player.vimeo.com`. Provider subresources run inside their own frames. File videos can use approved external HTTPS origins, but none are configured; add their exact origins to the observed media policy when supplied. Vercel preview toolbar origins must be measured on the real preview; do not pre-authorize wildcards.

Before enforcing resource CSP: review browser violations on real routes/embeds and Vercel previews, choose tested hashes or a nonce strategy compatible with static rendering/caching, and configure a privacy-reviewed reporting destination if needed. No collector exists: current reports are console-only. Do not invent a report endpoint. [OWASP CSP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html) supports a staged Report-Only rollout; report-only is not XSS enforcement. The independent enforced framing/object/base policy remains active.
